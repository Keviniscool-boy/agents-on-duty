# 01 · 系统架构说明书

版本 1.0.0 · 2026-11-04 · 对应代码分支 `feat/product-fix`（main = bbdd5e6 + 产品化修复）

## 1. 总体拓扑

```
浏览器（React 19 + Vite，:8080/nginx）
   │  httpOnly Cookie 会话 · SSE 阶段流 · REST
   ▼
FastAPI（:8000）
   ├── 认证会话层：JWT(HS256) + httpOnly Cookie / Bearer，登出即吊销
   ├── 业务 API：订单 / 退款 / 工单 / 知识检索 / 工作台 / 管理端
   ├── 聊天编排：LangGraph 状态图（异步，AsyncSqliteSaver 持久化检查点）
   ├── 工具协议：MCP Client ──▶ MCP Server（订单/退款/工单/知识/风险）
   │                   └─ 运行时故障 → 进程内备用工具（同一幂等存储）
   └── 横切面：TraceId 中间件 · 审计事件 · 指标 · 限流
           ▼
存储层：MySQL 8 · Redis 7 · SQLite(账户/幂等/检查点/售后) · FAISS(知识向量)
```

部署形态：`docker compose` 单机四容器（mysql / redis / app / frontend）。横向扩展受
SQLite 与单实例指标限制（见 §7 能力边界）。

## 2. Agent 编排（LangGraph）

图节点与走向：

```
supervisor_route
   ├─ 确定性路由（零模型）：问候/兜底词表 → fallback
   │                        转人工词表（转人工/人工客服/找人工…）→ ticket_handler
   │                        订单号/工单动作词表 → ticket_handler
   │                        政策关键词 → knowledge_rag
   ├─ 模型路由（兜底以上未命中时）：LLM 三分类，非法标签落 fallback
   ▼
knowledge_rag ──▶ compliance_checker ──▶ synthesize ──▶ END
ticket_handler ─┬─ 退款建单成功 → human_review（持久化中断，等客服决定）
                └─ 其余（含确定性转人工建单）→ compliance_checker → synthesize
fallback ──▶ compliance_checker（固定话术只走规则检查）
compliance_checker ─┬─ 通过/重试耗尽 → synthesize
                    └─ 未通过且未耗尽 → rewrite → compliance_checker
human_review ──▶ synthesize
```

关键设计：

- **确定性优先**：问候、转人工、订单号类请求在路由层由词表直接决定，不消耗模型调用；
  实测问候 819–952ms、转人工 734–831ms（N=5，单机 compose）。
- **人工中断（HITL）**：退款建单后 `interrupt()` 暂停，载荷即客服工作台"交接单"；
  客服决定后 `Command(resume)` 恢复。检查点由 `AsyncSqliteSaver` 持久化，服务重启可恢复。
- **恢复可靠性**：`handoff_outbox` 发件箱（UNIQUE(refund_id, action) + 5 分钟租约）把
  "客服决定"与"图恢复"解耦；三重校验（会话归属 / 检查点 user_id / 中断载荷匹配）后才恢复；
  失败释放租约回 pending，可手动重试。
- **同会话串行**：`session_turn_locks` 轮锁防止并发消息踩踏暂停线程。

## 3. 合规双检

1. **规则检查（始终执行）**：PII 正则（手机号/身份证/银行卡/邮箱）与禁词表；
   命中即拦截并脱敏。
2. **模型检查（按需）**：规则通过后由 LLM 依上下文深度检查；**15 秒超时或模型异常时
   降级为规则结果**并记录可诊断日志（`sub_results.compliance.degraded`），不产生未定义状态；
   返回非法 JSON 按保守拒绝处理。
3. **固定话术豁免**：问候/兜底/确定性转人工的系统话术标记 `fixed_reply`，跳过模型检查
   （规则检查仍执行）；合规重写产生的新文本不享受豁免。

## 4. 知识服务

- 源文件：`knowledge_base/` Markdown，带 doc_id / 版本 / 生效失效日期 / 发布状态元数据；
  过期与未发布版本自动排除，多版本冲突显式报错。
- 检索：FAISS 向量 + 关键词混合（RRF 融合），LLM 重排取 Top3；回答强制携带来源片段。
- 拒答策略：检索为空、置信度不足（阈值 0.55）、政策冲突时明确拒答并建议转人工。
- 索引身份校验：元数据记录建索引时的 provider+model，与当前配置不一致即丢弃重建，
  防止不同向量空间混用。
- 降级：embedding 服务不可用时检索接口返回 503（`knowledge_unavailable`），Agent 层
  拒答并转人工；旧索引保留，服务不中断。

## 5. 工具层（MCP）

| 工具 | 语义 | 幂等机制 |
|---|---|---|
| `order_query` / `order_list` | 查询本人演示订单 | 只读 |
| `refund_apply` | 提交退款申请（待人工审核） | 用户+幂等键唯一索引，重复返回原单 |
| `ticket_create` | 创建人工工单 | 内容指纹 + 会话幂等键，重试不重复建单 |
| `knowledge_search` | 知识检索（稳定 API） | 只读 |
| `risk_check` | 交易风险等级（演示规则） | 只读 |

- 服务端身份注入：`user_id` / `session_id` / `idempotency_key` 从服务端上下文填充并从
  LLM 可见 schema 中剔除，防伪造。
- 降级链：MCP 超时/连接失败 → 有限重试 → 进程内本地工具（同一 SQLite 幂等存储）；
  工具调用事件（含 retries/error_type/fallback）写入审计。

## 6. 可观测性

- 每请求生成/透传 `X-Trace-Id`（中间件，格式白名单校验）。
- `admin_events` 审计：角色变更 / 合规命中（仅固定代码不落原文）/ 节点运行 / 工具调用
  （含 `intent=handoff`）/ 模型调用（次数、耗时、错误类）。
- `AgentMetrics`：进程内指标汇总，`/api/metrics` 仅供 agent/admin。
- SSE 阶段事件：节点级中文状态（"正在判断问题类型"等），不承诺无法保证的完成时间。
- `/health`：知识库状态（ready/degraded/empty/unknown）+ 版本。

## 7. 能力边界（如实声明）

- 单机 SQLite：账户、工单幂等、检查点、售后库均为单文件，不支持多实例共享。
- 指标为进程内存态，重启归零。
- MySQL 为"兜底存储"角色：工作记忆/会话等在 MySQL 不可用时降级进程内，恢复后自动回切。
- 演示数据：订单/退款为模拟；审核通过不代表真实退款。
- Pi 知识助手为独立实验目录（`experiments/`），不参与主链路。
