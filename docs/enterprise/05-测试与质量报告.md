## 3. 质量属性验证

| 属性 | 证据 |
|---|---|
| 幂等 | 重复退款/工单返回原单；8 线程并发仅建一单（BEGIN IMMEDIATE，真实 MySQL 用例） |
| 可恢复 | 服务重启后从持久化检查点恢复人工审核；outbox 租约防重复恢复；失败可手动重推 |
| 降级有序 | Redis/MySQL/MCP/embedding 任一不可用均有明确降级路径与用户可见文案，不 500 裸奔 |
| 不伪装成功 | 合规超时降级带 `degraded` 标记；SSE 失败事件 + 前端看门狗；500 文案明确可重试 |
| 零信任输入 | 服务端身份注入覆盖 user_id/session_id/idempotency_key/username；正文伪造无效（测试钉住） |
| 性能（确定性路径） | 问候 819–952ms、转人工 734–831ms（N=5，单机 compose，零模型调用） |
| 可观测 | 每请求 trace_id 贯通审计；工具事件含 retries/error_type/intent |

## 5. 已知限制（不隐瞒）

- 真实模型下的 p50/p95 基准未建立（控制在真实 API 配额内）；测量方法已固化（N 次端到端
  计时 + 环境记录），可随时执行。
- 评测套件（`evaluation/`）的路由/RAG 质量分为脚本化实测，需运行中的服务与模型凭证；
  版本化对照工具（`compare.py`）要求套件版本与模型配置一致。
- Pi 与 LangGraph RAG 的真实模型端到端对比未执行（roadmap 如实标注"保守决定"）。
- 单 worker 假设：指标与进程内限流降级均绑定单进程。
